# BIMP for Sandbox

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
![s&box addon: rexi/bimp_sandbox](https://img.shields.io/badge/addon-rexi%2Fbimp__sandbox-555.svg)

**Media Screen** and **Media Speaker** entities for the official s&box **Sandbox** gamemode, powered by the
[BIMP media player](https://github.com/Claw256/sbox-bimp) library. Spawn a screen or a speaker from the spawn menu, and
everyone on the server watches or listens together, in sync: YouTube, Twitch, Kick, SoundCloud, live streams and
plain media links.

| Entity | Package | What it is |
|---|---|---|
| Media Screen | [`rexi.bimp_screen`](https://sbox.game/rexi/bimp_screen) | A TV screen with on-screen controls |
| Media Speaker | [`rexi.bimp_speaker`](https://sbox.game/rexi/bimp_speaker) | An audio-only speaker with a spectrum display |

## Using them in Sandbox

1. Open the spawn menu (**Q**) → **Entities**. Find them under **Fun** (or search "Media").
2. Spawn one, look at it and press **USE** to open the remote. Paste a link and press **Play now** or **Queue**.
3. Everything else works as in BIMP: point at the screen for its controls, pick your own resolution and audio
   language, use a controller. See the [BIMP README](https://github.com/Claw256/sbox-bimp#readme) for the details,
   the supported sites and the settings.

Who can control a spawned player follows BIMP's defaults: anyone can play, pause and queue.

## How it works

Sandbox's spawn menu lists "Sandbox Entity" assets (`.sent`) and packages of type `sent`. Each entity here is a
`.sent` published as its own package:

- **Media Screen** (`rexi.bimp_screen`) carries BIMP's compiled code (`IncludeCode` on).
- **Media Speaker** (`rexi.bimp_speaker`) carries no code and references the screen package, so BIMP is only ever
  loaded once, whichever you spawn.
- Each entity's prefab inherits BIMP's own prefab (`prefabs/bimp_screen.prefab`, `prefabs/bimp_speaker.prefab`) and
  adds a `Rigidbody`, so Sandbox's physgun and physics can move it. Changes to BIMP's prefabs carry over.

| Path | |
|---|---|
| `bimp_sandbox.sbproj` | The addon project: type `addon`, parent package `facepunch.sandbox` |
| `Assets/entities/*.sent` | The two entities (title, category, prefab) and their publish settings (`.sent.meta`) |
| `Assets/entities/*.prefab` | The entities' prefabs: a `Rigidbody` around an instance of BIMP's prefab |
| `Assets/scenes/bimp_test.scene` | A test scene with a screen and a speaker, for trying BIMP in Sandbox from the editor |
| `Code/BimpSandbox.cs` | The addon's own code, which links BIMP so its components load |
| `Libraries/bimp` | The BIMP library, as a git submodule of [Claw256/sbox-bimp](https://github.com/Claw256/sbox-bimp) |
| `Editor/PublishEntities.cs` | An editor MCP tool, `bimp_publish_entities`, that checks or publishes both entities |

## Building from source

```bash
git clone --recursive https://github.com/Claw256/sbox-bimp-addon.git
# or, in an existing clone:
git submodule update --init
```

Open `bimp_sandbox.sbproj` in the s&box editor; `scenes/bimp_test.scene` plays BIMP inside Sandbox.

To publish, use each entity's **Publish** button in the asset inspector (not the Batch Publisher, which skips
compiling the code): `media_screen.sent` first, then `media_speaker.sent`. Publishing the whole addon project isn't
needed, and would also upload the test scene.

To pick up a newer BIMP, with play mode stopped:

```bash
git submodule update --remote Libraries/bimp
git add Libraries/bimp
git commit -m "Update BIMP"
```

then republish `media_screen.sent`.
